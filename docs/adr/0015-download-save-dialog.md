# 0015. 下载落点由用户在保存对话框确认

- 状态：已采纳（取代 [0014](./0014-instance-download-controlled-path.md) 的落盘方式）
- 日期：2026-11-02

## 背景

0014 打了两个补丁：先解决「嵌入页面里的会话导出点了没反应」，再把落盘改为「主进程定路径，静默写进系统下载目录」。放行本身是对的，第二半在真实使用中露出问题：用户点导出后界面没有任何反应，文件已经躺在下载目录里——既不知道下载发生了、也不知道落到哪里，更没法在保存前改个名字或换个位置。浏览器之所以能这么干，是因为它有下载列表与地址栏里的下载提示；Hub 两者都没有，静默落盘就成了「点了没反应」的另一种形态。

## 决策

`will-download` 里不再调用 `setSavePath`，改为只给保存对话框预填默认路径（`setSaveDialogOptions`）：

1. **每次下载都弹系统保存对话框**，用户确认后才落盘。落点因此总是用户看过的，路径的每个片段要么来自主进程的默认值，要么来自用户在对话框里的选择，仍不来自 renderer 或 IPC 输入。
2. **默认路径 = 系统下载目录 + 清洗后的建议文件名**（`download.save.title` 的标题与本地化按钮文案一并给到）。沿用 0014 的 `sanitizeDownloadFilename`。
3. **重名自动加序号**（`uniqueDownloadPath`）：默认值是 `export (1).json` 而不是 `export.json`，避免用户在确认时被系统的覆盖提示劝退；真正覆盖与否仍由用户在对话框里决定。
4. **下载目录不可用时对话框照常打开**，只是没有预填路径。两条分支的差别只剩「有没有默认值」，不再有两种下载行为。
5. 中断通知（0014 的第 5 条）保持不变；用户在对话框里取消属于 `cancelled`，不提示。

## 被否决的备选

- **维持静默落盘，只加「已下载」通知**：能告诉用户「有文件下来了」，但改不了落点、也改不了名字；用户想把导出放进项目目录仍要事后去 Finder 里挪。
- **静默落盘 + 下载完成后提供「在文件夹中显示」**：比通知多一步补救，仍不是保存前决策，且需要一个 Hub 自己的下载列表来承载入口（本轮不引入窗口级 UI）。
- **只在首次下载时询问、之后记住目录**：用户明确要的是每次都能选路径；「记住」还需一个设置项与清除入口，收益不抵成本。
- **让 renderer 指定保存目录**：仍踩「IPC 不得接受可被 renderer 用来执行任意路径的输入」红线。

## 后果

- 会话导出等下载与浏览器「下载前询问保存位置」同构：每次都看得见、可改落点；`defaultPath` 已去重，默认确认即可，不必与覆盖提示打交道。
- `src/main/instance-download.test.ts` 锁定「只设对话框、不设 savePath」「默认路径清洗 + 去重」「目录不可用仍开对话框」；`workspace-host.test.ts` 锁定默认路径由主进程给出。
- 代价是每次导出多一次确认点击；这是把「静默下载」换成「用户知情」的直接成本。
