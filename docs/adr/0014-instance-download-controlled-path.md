# 0014. 实例分区下载受控放行

- 状态：已采纳（落盘方式被 [0015](./0015-download-save-dialog.md) 取代：改由保存对话框确认落点）
- 日期：2026-11-01

## 背景

dsh web 的会话导出走浏览器下载通道：页面发起下载，Chromium 在实例分区 session 上触发 `will-download`。工作区视图（workspace-host）此前对该事件无条件 `event.preventDefault()`，下载被静默取消——浏览器里同一个功能可用，Hub 里点击无任何反应、无报错。分离实例窗口（window-host）与工作区共享 `persist:inst-<id>` 分区 session，但不安装该监听，行为随「先打开工作区还是先开分离窗口」漂移。

当初无条件拦截的动机是安全边界：不让嵌入页面往磁盘写任意文件。拦截确实封死了任意写，但代价是功能整体不可用，且「页面可控的落盘」并没有被治理，只是被一刀切禁止。

## 决策

把「无条件拦截」改为「受控放行」，实现收敛在 `src/main/instance-download.ts`，由 workspace-host 与 window-host 共同安装（`createOncePerSession` 守卫，同分区只装一次）：

1. **保存路径由主进程决定**：默认 `app.getPath('downloads')` + 清洗后的建议文件名。路径的每个片段要么来自主进程常量，要么来自用户在原生保存对话框里的选择，绝不来自 renderer 或 IPC 输入——不触碰「IPC 不得接受任意路径」红线。
2. **页面建议名按不可信输入清洗**（`sanitizeDownloadFilename`）：只取最后一段路径（丢弃 `../`、绝对路径、盘符），去控制字符与 Windows 非法字符，前导点与 Windows 保留设备名加处理，超长截断保留扩展名。
3. **重名不覆盖**（`uniqueDownloadPath`）：冲突时插入 ` (1)`、` (2)` 序号；远端实例无法借同名覆盖用户已有文件。
4. **默认目录不可用时回落原生保存对话框**：目录取不到或不可写时不设 `savePath`，下载不被取消，由 Electron 弹保存对话框让用户手选路径（方案 A 作为兜底，而非唯一路径）。
5. **中断要出声**：`done` 为 `interrupted`（如 SSH 隧道断开）时发一次系统通知，文案走 i18n 目录（`download.interrupted.*`）；用户在保存对话框主动取消不提示；通知是旁路，发送抛错不冒泡进下载收尾。
6. 两处宿主安装同一实现，消除「先开哪个窗口决定下载能不能用」的行为漂移。

## 被否决的备选

- **维持无条件拦截**：会话导出等功能在 Hub 内永久不可用，且没有任何用户可见的失败提示，属于静默吞功能。
- **只放行同源 `content-disposition: attachment` 白名单**：规则写在 URL 层，插件与后续新导出路径极易绕过或误伤；判定散落两处宿主，漂移风险重。
- **让 renderer 指定保存目录**：直接踩「IPC 不得接受可被 renderer 用来执行任意路径的输入」红线。
- **只做方案 A（每次都弹保存对话框）**：每次导出都多一次交互，与浏览器默认体验不一致；作为目录不可用时的兜底保留。

## 后果

- Hub 内会话导出等下载可用，行为对齐浏览器：默认静默落系统下载目录，目录异常时弹保存对话框。
- 远程实例（local/ssh/http 三种传输）不需要任何分支代码：下载永远在本机落盘，差异只体现在文件名信任度与连接中断概率上，前者由清洗+改名覆盖，后者由中断通知覆盖。
- 安全姿态从「禁止写盘」变为「限定写盘位置与文件名」；`src/main/instance-download.test.ts` 锁定清洗、改名、回落与通知行为，`workspace-host.test.ts` 锁定「不拦截 + 路径由主进程给定」。
- 下载文件由用户自行保管（内容含完整会话记录）；写入系统下载目录是明文落盘，与浏览器导出一致。
