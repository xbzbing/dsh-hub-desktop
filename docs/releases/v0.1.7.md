- 发布日期： 2026-11-01
- 标签： `v0.1.7`

## 概述

本版本把插件升级对齐 dsh 官方的安装方式：**先停止并移除旧版本，再安装新版本**，安装失败时自动把旧版本装回去。同时设置页新增「检查更新」（读取 GitHub Release），并放行实例页面的全屏权限，让插件里的文件阅读器不再卡在「宿主未响应」。

## 亮点

- **插件升级改为「先停止并移除、再安装」**：此前 hub 只用 `dsh plugin add name@version` 直接在运行中的版本上覆盖安装。dsh 自身的 `updateBundle`（Web 插件页的 Update）在有 HMR 时走的是另一支——先 `removeBundle` 停掉旧版本插件、卸载其模块并删除包映射，再安装目标版本；新版本因此按**全新装载**启动，而不是在原映射上做模块代替换。现 hub 与之对齐：HMR 可用时先移除再安装；目标版本装不上或起不来时，用同一安装源把旧版本装回，并在错误里说明装回结果（回装也失败时明确「插件可能已不在 profile 中」）。无 HMR 的 profile 仍直接覆盖安装并提示重启。升级不改变启用状态——移除会把包移出加载清单，因此升级前已禁用的插件装回后会重新禁用。决策见 ADR-0013。
- **设置页「检查更新」**：新增应用自身的更新检查——主进程读取 GitHub Release（最近 30 条，跳过 Draft，按 tag 解析版本并取最高者），与当前版本比较后给出「已是最新」或「发现新版本 vX」，并可直接打开发布页。仓库地址由主进程从 `HOMEPAGE_URL` 解析，渲染层不传 URL；5 秒超时，网络失败与上游格式异常都收敛成面向用户的失败文案，不会拖住按钮。
- **全屏权限放行**：实例页面的 `Element.requestFullscreen()` 此前被权限策略拒绝。Electron 对被拒的全屏请求不会给页面一个干净的 reject，请求悬置、页面只能靠自己的超时提示失败——表现就是打开插件里的文件阅读器后卡在「宿主未响应」。现与剪贴板、语音输入一并放行（摄像头仍拒绝）。

### 修复与体验

- **升级确认文案**：确认框底部原写「升级会短暂中断正在使用的工作区」，只说中断、不说机制。改为「升级会先停止并移除旧版本，再安装新版本；依赖该插件的功能会短暂中断」，与真实行为一致。
- **发布脚本接受裸 `--`**：`pnpm release:publish -- --publish` 会把 pnpm 透传的 `--` 也交给脚本，参数解析失败。现忽略该分隔符，正式发布命令按 runbook 原样可用。
- **发布文档**：runbook 回写 v0.1.6 的走通记录，并修正发布说明里的提交计数。

### 依赖与测试

- 开发依赖跟随 Dependabot：electron-builder 26.15.3 → 26.18.0、typescript-eslint 8.71.2 → 8.72.0、zustand 5.0.15 → 5.0.16；运行时依赖仍为零（`dependencies` 为空由测试守护）。
- 新增升级流程的单测（先移除再安装、失败回装、回装也失败、禁用态保留、读不出版本时退回覆盖安装）与插件页 E2E 断言（一次 `remove` + 一次 `add`）；单测 1611 项、E2E 64 项全部通过。
- 新增 ADR-0013，记录本次升级机制与 dsh 官方口径的对齐。
