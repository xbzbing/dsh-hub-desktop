# DSH Hub v0.1.16

- 发布日期: 2026-11-19
- 标签： `v0.1.16`

## 分发方式

- `windows-unsigned`

## 产物

- `DSH-Hub-Setup-0.1.16.exe`（Windows x64 NSIS 安装包，未签名）
- `SHA256SUMS.txt`（上述安装包的 SHA-256 校验清单）

> 安装包未经代码签名，Windows 首次运行会出现 SmartScreen「未知发布者」提示——点「更多信息 → 仍要运行」即可继续。下载后请用 `SHA256SUMS.txt` 校验完整性。macOS 暂不提供官方二进制，仍需从源码构建。

## 概述

本版重做插件管理的三处交互：列表可按名称或包名搜索，本机与 GitHub 安装的插件不再查询 npm 更新，安装进度支持转到后台；同时修掉一处会让插件列表整页空白的 profile 残留锁。随包运行时跟进到 Electron 45.3.4。

## 亮点

- **插件搜索**：插件卡标题栏新增搜索框，按显示名称或包名即时过滤，不区分大小写；无命中给出「没有匹配的插件」，清空即恢复。过滤只改变列表内容，不改变插件状态；「一键检查」随之只覆盖当前列出的、可查更新的插件。
- **本机与 GitHub 安装的插件不再查 npm 更新**：这类插件的版本由安装来源决定，查询 npm 只会得到 404 或陈旧结果。现在列表不再为它们回填发布时间，`检查升级` 按钮保留原位但置于禁用态，悬停或键盘聚焦时说明「本地/GitHub 安装的插件不支持检查 npm 更新」，`一键检查` 自动跳过——整批检查里不再出现针对这类插件的失败项。
- **安装可放到后台**：进度对话框在安装下发后提供「放到后台」，转后台后与普通安装行为一致，可以继续查看、切换其它插件；后台安装仍在进行时卡片上有明确提示，完成后列表自动刷新。安全检查判定有风险时，「安装后立即启动」默认不勾选，需用户主动打开。
- **插件列表不再被残留写锁卡死**：dsh 的 profile 写锁若在「建文件 → 写 PID」之间被打断，会留下 0 字节锁；其自身回收逻辑永远判定它仍被持有，于是每条插件命令都空等 120 秒——列表整页空白、安装失败，重启应用也不恢复。现在 Hub 在执行插件命令前预检该锁：无 PID 且已过 2 秒、或记录的进程已不存在时，把锁移到 `<dataDir>/stale-locks/` 备份后再执行；活锁一律不动。列表命令的超时收紧到 30 秒，写锁导致的失败改成「哪个文件、被谁挡住」的可操作说明，不再透出 dsh 堆栈。
- **Electron 45.3.4**：从 45.3.3 升到 45.3.4，仍在 major 45 内精确锁定；随包 Chromium 156.0.8078.100、Node 24.22.3、undici 7.30.2 与上版一致。随包分发的 npm CLI 同步升到 12.2.3，装机版插件安装使用这次构建的 npm。
