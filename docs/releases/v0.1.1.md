# DSH Hub v0.1.1

- 发布日期： 2026-09-20
- 标签： `v0.1.1`

## 分发方式

- `source-only`

## 概述

本版本聚焦 Windows 平台完整兼容与 CI 质量门强化：外部 dsh web 探测、运行时发现、单测与 E2E 全部质量门现已在 windows-latest 上运行并通过；同时修复工作区重复打开导致的原生视图边界竞争，并让 Linux 无头环境下的凭据保险库与真实桌面行为一致。

GitHub Release 当前仅发布标签、发布说明以及 GitHub 自动生成的源码归档（`Source code (zip)`、`Source code (tar.gz)`）。不提供官方 `.app`、`.dmg`、`.zip`、`.exe`、自动更新元数据或校验和文件。

## 从源码构建

需要 Node 22+、pnpm 11，以及目标平台对应的构建环境：

```bash
pnpm install
pnpm build
pnpm test
pnpm dist:mac    # macOS 本地构建
# 或 pnpm dist:win  # Windows 本地构建
```

本地构建生成的产物未签名、未公证，仅适用于开发、本机验证或受控测试；构建成功不代表可以安全公开分发。请勿将它们作为官方 Release 资产重新上传。

## 亮点

- **Windows 平台兼容**：外部 dsh web 进程探测（`Get-CimInstance` + `netstat`）、运行时 PATH 探测、注册表与审计相关单测完成跨平台适配；CI 新增 Windows 作业执行 lint、typecheck、test、build 与 E2E 全量质量门。
- **Linux 无头环境保险库可用**：通过 `--password-store` 显式指定 safeStorage 后端并补齐 libsecret 依赖，凭据保险库在无头环境与真实桌面行为一致（此前回退 basic_text 被判为降级、跨重启凭据丢失）。
- **契约测试对齐官方插件仓库**：CI 契约作业固定 checkout `xbzbing/dsh-auth-gateway` 并在每次提交上运行。

### 修复

- Windows 下命令行含换行的进程（如 `node -e` 启动的外部 dsh web）在扫描输出中被断行丢失，导致探测不到
- 已打开的工作区再次收到打开请求时，原生视图被隐藏后重开、边界短暂归零（0,0）
- 工作区打开在途时，重复的 running 状态事件不再重复触发打开
- 保险库降级审计记录具体加密后端枚举，便于排查系统钥匙串选择失败
- 校验和脚本主入口判定不再依赖在 Windows 上失效的 argv 归一化

### 测试与 CI

- Linux E2E 补齐 dbus + gnome-keyring 密钥环，显式校验 Secret Service 可用后再运行
- E2E 失败时收集错误上下文与审计日志用于诊断；凭据保险库密文目录永不上传，测试数据纪律已在文档中明确
- E2E 无头环境自动拒绝 dsh 下载确认原生对话框；启动参数统一收敛到共享模块
- 跨平台单测：平台相关行为固定平台断言，POSIX 专属用例（0600 权限、AF_UNIX、ControlPath 长度）在 Windows 上跳过

## 当前限制

- 未提供签名和公证的官方桌面安装包，自动更新不对外可用。
- 首次创建本地实例可能需要联网准备 dsh 运行时；内网环境可设置 `DSH_HUB_NPM_REGISTRY`。

恢复官方二进制分发需要 Apple Developer Program、Developer ID 签名、公证与 staple、干净机器安装验证，以及可复核的更新元数据和校验和。完整门槛见 [发布策略](https://github.com/xbzbing/dsh-hub-desktop/blob/v0.1.1/docs/release-policy.md)。
