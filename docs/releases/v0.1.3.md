# DSH Hub v0.1.3

- 发布日期： 2026-10-09
- 标签： `v0.1.3`

## 分发方式

- `windows-unsigned`

## 产物

- `DSH-Hub-Setup-0.1.3.exe`（Windows x64 NSIS 安装包，未签名）
- `SHA256SUMS.txt`（上述安装包的 SHA-256 校验清单）

> 从本版本起，Release 附带本地构建的 **未签名** Windows 安装包。安装包未经代码签名，Windows 首次运行会出现 SmartScreen「未知发布者」提示——点「更多信息 → 仍要运行」即可继续。下载后请用 `SHA256SUMS.txt` 校验完整性。macOS 暂不提供官方二进制，仍需从源码构建。

## 概述

本版本是功能大版本：新增 **dsh 版本管理**（详情页检测与一键升级、新建实例版本下拉、安装进度实时可见）、**环境变量重新检测**（无需重启应用即可让实例获取新装的 git/node 等）、**插件操作日志按天归并**、**侧栏实例快捷键**、详情页底部信息栏、设置页空间管理、应用内「关于」面板，并合入一轮整仓评审的必须项修复。

## 亮点

- **dsh 版本管理**：详情页显示当前版本与镜像最新版本，一键升级走「停止 → 安装 → 版本写回 → 重启」的单飞编排，进度实时驱动进度条与底部信息栏日志；新建实例的版本下拉默认「跟随最新稳定版」，可显式选定历史版本。版本元数据从安装队列拆到独立队列并加缓存，检查更新与版本列表不再被安装阻塞；npm 镜像可配置（`DSH_HUB_NPM_REGISTRY` 或设置页镜像项）。
- **环境变量重新检测**：设置页新增「重新检测环境变量」按钮，刷新主进程缓存的登录 PATH / 登录 shell 环境后，询问是否重启运行中的本机实例，让启动应用后才安装的 git/node 等被实例获取，而不必重启整个应用；详情页重启实例时也会先刷新一次缓存。
- **插件操作日志按天归并**：插件安装/升级产生的 `operation-*` 目录在沉降后并入按天的 `plugin-operations.<YYYY-MM-DD>.log`，默认保留 30 天，避免大量零散目录堆积。
- **侧栏实例快捷键**：按住切换修饰键（macOS 为 ⌘，Windows/Linux 为 Alt）满 0.5 秒，侧栏按当前可见顺序显示 #1–#9 序号；修饰键 + 数字立即切换实例。工作区原生视图持有键盘焦点时，主进程按白名单转发修饰键与数字组合，切换在工作区内同样生效。
- **详情页底部信息栏**：常驻单行滚动展示运行状态与安装进度日志（超长截断省略、不换行），「更多」打开宽屏日志对话框，支持复制与清空；运行环境卡片新增「关闭实例」。
- **设置：空间管理与界面语言**：新增隔离空间管理入口；界面语言可跟随系统或显式固定中文/英文，打包不再裁剪 Chromium 语言包。
- **应用内「关于」面板**：以独立叠加窗口浮在当前页面之上，展示应用版本、项目主页，以及实际运行的 Electron、Chromium、Node.js、V8 版本。
- **远程实例登录引导**：经向导新建的远程实例（http/ssh）运行后先探测认证，若使用 dsh-auth-gateway 需登录，则先弹出登录框引导登录、登录成功后再打开工作区，而不是直接打开工作区显示网关登录页。

### 修复

- **后台不再抢占其它应用焦点**：实例停止/断开、工作区变为可见等后台事件，只在 Hub 窗口当前已聚焦时才交还或转移键盘焦点；应用不在前台时跳过，避免 macOS 下 `webContents.focus()` 把窗口顶到最前、抢走其它应用（如如流）的焦点。
- **升级插件后同步发布时间**：升级完成后直接取新版本的发布时间并落成快照，详情页「发布时间」无需再次检查即可显示（取不到时清掉旧版本的陈旧快照）。
- **mac 升级插件兼容既有 profile**：按平台决定随包 pnpm 在 PATH 的位置——Windows 前置（系统 pnpm 全局 shim 已损坏），mac/Linux 后置兜底，优先用与既有 profile 的 store 版本匹配的系统 pnpm，消除 `ERR_PNPM_UNEXPECTED_STORE`。
- **整仓评审必须项**：删除幻影实例提前短路；凭据保险库恢复默认保存并对齐文档；打开工作区加载页超时兜底，避免卡死；SSH socket 目录改 0700 并校验属主，防共享临时目录劫持；semver tilde 通配上界修正。
- 打包产物在 ready 前把 Chromium 语言钉为系统语言，修复新实例整站显示英文。
- 对话框统一支持 Escape 关闭、焦点圈闭于对话框内、小窗口限高滚动、页脚常驻。
- 「关于」改为独立叠加窗口，打开/关闭不跳转、不隐藏工作区视图；隐藏工作区原生视图时把键盘焦点交还宿主渲染层。
- 实例详情「连接方式」「运行环境」卡片放开文本选中复制；数据目录由主进程预计算，消除混合分隔符。
- Windows 下 npm 调用方式解析修正；打包前显式准备 Electron 二进制；重建应用图标，修复渲染为黑块。

### 测试与 CI

- CI 覆盖 ubuntu（xvfb + gnome-keyring）与 Windows 双平台，单元测试与 E2E 全绿。
- 发布演练支持 `source-only` 与 `windows-unsigned` 两种分发模式，并对资产清单做形态白名单校验：mac 二进制、`latest-*.yml`、`.blockmap` 任何模式都拒绝。

## 从源码构建

需要 Node 22+、pnpm，以及目标平台对应的构建环境：

```bash
pnpm install
pnpm build
pnpm test
pnpm dist:win        # Windows 本地构建（Windows 上）
# 或 bash docs/local/build-win-local.sh  # mac 上交叉构建 Windows 包
# 或 pnpm dist:mac   # macOS 本地构建（未签名 .app，仅本机验证）
```

本地构建生成的产物未签名、未公证；macOS 产物仅适用于开发、本机验证或受控测试，不随发布上传。

## 当前限制

- Windows 安装包未签名，首次运行会触发 SmartScreen 提示；macOS 不提供官方二进制，需从源码构建。
- 首次创建本地实例可能需要联网准备 dsh 运行时；内网环境可设置 `DSH_HUB_NPM_REGISTRY`。
- 版本检查仅覆盖 hub 托管的本地实例；SSH / 远程实例暂无获取其 dsh 版本的途径。镜像 `latest` 标签滞后于新发布时，以版本列表最大值为准。

Windows 代码签名与 macOS 二进制分发的门槛见 [发布策略](https://github.com/xbzbing/dsh-hub-desktop/blob/main/docs/release-policy.md)。
