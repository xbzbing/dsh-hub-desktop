### #1 只有左侧菜单标题栏能拖动窗口,右侧分区标题栏不能 —— ✅ 已修（本轮）

### #2 创建实例时,本机已有 dsh 就不该再下载安装新版本 —— ⏳ 待修（**策略已由用户拍定**）

- **期望**:优先复用/链接本机**已有**的 dsh;仅在确实缺失时才下载安装。
- **用户已拍定的优先级（2026-09-16）**:
  1. **优先复用 hub 已装的同版本**（`<dataRoot>/runtimes/` 内已存在的同版本运行时,直接用,不重新下载）;
  2. 其次**探测 PATH 上本机已安装的 dsh**（系统环境）;
  3. 两者都没有才**下载安装** —— 且**下载前必须让用户确认**（不得静默联网拉取）。
- **调查起点**:`src/main/local-runtime/local-runtime.ts` 的 `ensureInstalled` / 版本解析 ——
  目前按实例配置的版本准备运行时（见 T3 测试「启动前经 ensureInstalled 准备运行时(指定版本直接用)」）,
  没有「探测既有 dsh 并复用」的路径,也没有「下载前确认」的交互。
- **实现要点**:
  - 复用 PATH 上的 dsh 时,版本口径要与实例配置的 `dshVersion` 比对;不匹配要不要允许?（**待定**,建议不匹配则回落到 hub 运行时）。
  - 复用系统 dsh 意味着**跨出 hub 的隔离目录**,安全边界变化:必须在文档与 UI 上讲清楚
    （该实例的 dsh 由用户环境提供,行为可能随用户升级而变）。
  - 「下载前确认」需要一个主进程 → 渲染层的**确认**往返（现有 IPC 信封是请求-响应式,
    确认属于新增交互,需按 AGENTS.md 的四步加通道,并考虑并发创建时的排队语义）。

### #4 远程实例最后一步确认时会弹出远程 dsh 的认证页,输入密码无反应;而主程序界面输入密码则成功 —— ⏳ 待定（需与 #5 一起改）

- **这个页面是什么**:`openView` 在 `src/main/index.ts:229` 用 `new BrowserWindow(...)` 打开的
  **独立实例窗口**,加载该实例 URL。它是"工作区"的载体 —— 但**不该**是独立窗口(见 #5)。
- **为什么在它里面输入密码没反应**:认证走的是**应用自己的**网关流程(主进程 `auth/gateway-client`
  + 成功后把 HttpOnly Cookie 注入该分区)。那个页面上的登录表单**不是**本应用的认证入口,
  因此在页面里提交不会驱动本应用的状态机;而在主程序 AuthPanel 里提交走的是 IPC 正路,故成功。
- **结论**:这不是"页面坏了",而是**入口错位** —— 正确顺序应是先经应用完成认证,再由应用注入
  Cookie,工作区随后自然以已登录状态呈现。修 #5(工作区内嵌)时应一并处理:
  未认证时不应把裸登录页甩给用户,而应引导到应用内的认证面板(设计 §5.2 的分步认证)。

### #5 点实例应默认打开「工作区」,现在打开的是「实例详情」;且「打开视图」弹出新页面 —— ⏳ 待修（与设计不符）

- **设计基线明确要求内嵌**:`design/dsh-hub-desktop.html:661`
  「工作区会**嵌在应用内**,断线自动重连,远程实例的登录与动态验证码也不用再切浏览器」;
  :747「工作区会**嵌在这里**,断开也不会丢失会话内容」。
- **当前实现**:`openView` → `new BrowserWindow`(`src/main/index.ts:229`)= **独立窗口**,与设计冲突。
- **另外**:左侧导航点实例后右侧默认渲染的是**详情页**(`DetailView`),而设计要求默认进**工作区**。
- **修复方向**:(a) 主窗口右侧支持内嵌 webview 承载工作区(`partition: persist:inst-<id>`);
  (b) 点实例默认切到工作区,详情作为次级页签/入口;(c) 保留独立的"在新窗口打开"作为**可选**动作
  (设计有 `external` 图标语义),但不再是唯一路径。
- **风险**:webview 内嵌涉及 Electron 的 `webviewTag` 与 `will-attach-webview` 加固 ——
  当前两个窗口都是 `webviewTag: false`(见 T12 走查 §2),内嵌方案**必须**重新做安全走查
  (URL 白名单、partition 隔离、禁止 nodeIntegration),不能直开 `webviewTag`。

### #6 侧栏收起时与左上角红绿灯按钮重叠 —— ✅ 已修（本轮）

- **定位**:折叠态 `.app-shell.rail .side-head` 原为 `padding: 20px 0 0`(零左内边距),
  而展开态靠 `html[data-platform='darwin'] .side-head { padding-left: 80px }` 给红绿灯让位;
  折叠态侧栏只有 **64px** 宽,横向没有 80px 可用 → 内容从 y=20 起就压到按钮上。
- **修复**:折叠态改为**纵向让位** —— 新增
  `html[data-platform='darwin'] .app-shell.rail .side-head { padding-top: 40px }`
  (28px 按钮带 + 间距)。**仅 darwin 生效**,Windows/Linux 无红绿灯、保持 20px 不变。
- **验证**:build ✅ · lint 0 · 护栏 20/20。**重叠是否完全消除需实机确认。**

### #7 实例总览里列表的状态原点是灰色,与实际状态不符 —— ⏳ 待修

- **调查起点**:`.status-dot`(`styles.css:749`,折叠态覆盖见 :873)、
  `src/renderer/src/lib/format.ts` 的 `toDisplayStatus`,以及总览页列表项渲染处。
- **可能原因**(需实测确认,勿臆断):总览/列表用的状态来源是注册表里的**持久字段**而非
  运行期事件(`onInstanceStatus`),或 `toDisplayStatus` 把未知/未订阅态一律落成灰。
- **验收**:列表圆点必须与该实例当下的运行态一致(运行中/已停止/错误/连接中等),
  且随状态事件实时更新。

## 建议:T15「工作区内嵌」独立任务(#4 + #5)

#4 与 #5 同根,且**牵涉新的攻击面**,不宜作为 UI 小改顺手做。建议单列为 T15:

**目标**:点实例默认在**主窗口右侧内嵌**打开工作区(设计 `design/dsh-hub-desktop.html:661/:747`
明确要求"嵌在应用内"),「实例详情」降为次级入口,「在新窗口打开」保留为**可选**动作。

**为什么必须重做安全走查**(而不是改几行 UI):
- 当前主窗口与实例窗口均 `webviewTag: false`(T12 走查 §2 确认),内嵌工作区**必须**开 webview
  → 直接新增一个渲染层可加载任意实例 URL 的面。
- 必须同时具备:URL 白名单(只允许该实例已注册的 origin)、`will-attach-webview` 强制覆写
  `preload`/`nodeIntegration`/`partition`(不信任页面传入的 webPreferences)、
  partition 仍按 `persist:inst-<id>` 隔离、`setWindowOpenHandler` 一律 deny、
  以及"未认证时不得把裸网关登录页直接呈现给用户"(见 #4,应引导至应用内认证面板)。
- 复用现有缝:`src/main/webview/open-view-plan.ts`(`buildOpenViewPlan`/`classifyViewResponse`)
  已承载 basePath 与 Cookie 决策,内嵌方案应让它继续负责"用什么 URL、带什么 Cookie"。

**验收(不可省)**:内嵌后必须**重跑 T12 的走查项**并出一份增量报告(webview 加固、
partition 隔离、导航策略、Cookie 注入不许回归);#4 的"输入密码无反应"要以
"未认证时进入应用内认证面板、认证后工作区自然呈现"的实测结果收口。
